# Campagna VAS 3 - stress della cache L2: column-major contro shared memory.
#
# La geometria M=2048, N=262144 e' intenzionalmente molto larga. In FP64:
# - A occupa esattamente 4 GiB, il doppio del caso 16384x16384;
# - X occupa 6, 12, 16, 40 e 64 MiB per k=3,6,8,20,32.
#
# X supera quindi i 4 MiB di L2 della Quadro RTX 5000 per ogni k. La campagna
# verifica se, fuori dal regime in cui X puo' risiedere interamente in L2, il
# riuso esplicito del tile di cuda_warp_smem compensa staging e barriere.
# Non si assume a priori che la shared memory debba vincere.
#
# Ogni kernel viene misurato esclusivamente con la propria configurazione
# selezionata nella Fase 1: column-major/BLOCK=128 e shared-memory/BLOCK=256.
# Il confronto e' quindi tra i migliori casi dei due kernel.
# Totale: 2 kernel x 5 k = 10 configurazioni.
#
# Esecuzione:
#   ./script/run_cuda_experiments.sh --suite experiments/fase_1_tuning/campagna_VAS_3_l2_stress.txt
